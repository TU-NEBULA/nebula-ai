# Nebula AI 모니터링 기준 가이드

## 🎯 핵심 모니터링 지표 & 판단 기준

### 1️⃣ 성능 지표 (Performance Metrics)

#### 📊 **HTTP 응답 시간 (Response Time)**
- **정상**: < 200ms (추천 API), < 100ms (헬스 체크)
- **주의**: 200-500ms 
- **경고**: 500ms-1s
- **위험**: > 1s

**📋 판단 기준:**
- 추천 시스템은 실시간 응답이 중요하므로 200ms 이하 유지
- 사용자 경험에 직접적 영향을 미치는 핵심 지표
- P95 응답시간을 중점 모니터링

#### 🚀 **처리량 (Throughput)**
- **정상**: 초당 10-50 요청 (일반적인 부하)
- **고부하**: 초당 50-100 요청
- **과부하**: 초당 100+ 요청

**📋 판단 기준:**
- 추천 요청 패턴 분석으로 트래픽 예측
- 피크 시간대 대비 용량 계획 수립

#### ❌ **에러율 (Error Rate)**
- **정상**: < 1%
- **주의**: 1-5%
- **경고**: 5-10%
- **위험**: > 10%

**📋 판단 기준:**
- 4xx 에러: 클라이언트 문제 (잘못된 요청)
- 5xx 에러: 서버 문제 (즉시 대응 필요)

### 2️⃣ 리소스 사용량 (Resource Utilization)

#### 🧠 **메모리 사용량**
- **정상**: < 70% (컨테이너 한계 기준)
- **주의**: 70-85%
- **경고**: 85-95%
- **위험**: > 95%

**📋 판단 기준:**
- 현재 310MB 사용 → 컨테이너 메모리 한계 확인 필요
- 메모리 누수 패턴 모니터링 (지속적 증가)
- GC 빈도와 메모리 해제 패턴 관찰

#### ⚡ **CPU 사용률**
- **정상**: < 60%
- **주의**: 60-80%
- **경고**: 80-90%
- **위험**: > 90%

**📋 판단 기준:**
- 추천 알고리즘 연산 집약적 → CPU 스파이크 정상
- 지속적 고사용률은 스케일링 신호

#### 💾 **디스크 I/O**
- **정상**: < 80% 활용도
- **주의**: 80-90%
- **위험**: > 90%

### 3️⃣ 비즈니스 메트릭 (Business Metrics)

#### 🎯 **추천 시스템 성능**
- **추천 성공률**: > 95%
- **개인화 점수**: 모니터링 및 트렌드 분석
- **클러스터 분산**: 균등한 사용자 분포

#### 👥 **사용자 행동 패턴**
- **활성 사용자 수**: 시간대별 패턴
- **요청 유형 분포**: 일반/클러스터/트렌드 추천 비율
- **응답 시간 분포**: 사용자별 경험 품질

### 4️⃣ 인프라 안정성 (Infrastructure Health)

#### 🐳 **컨테이너 상태**
- **실행 중인 컨테이너**: 모든 서비스 정상
- **재시작 횟수**: 빈번한 재시작은 불안정성 신호
- **메모리/CPU 한계**: 컨테이너 리소스 제한 준수

#### 🗄️ **데이터베이스 연결**
- **연결 풀 사용률**: < 80%
- **쿼리 응답 시간**: < 100ms
- **데드락/타임아웃**: 최소화

## 🚨 알람 설정 권장사항

### ⚠️ **경고 레벨 알람**
- 응답 시간 > 500ms (5분간 지속)
- 에러율 > 5% (1분간 지속)
- 메모리 사용률 > 85%
- CPU 사용률 > 80% (10분간 지속)

### 🔴 **위험 레벨 알람**
- 응답 시간 > 1s
- 에러율 > 10%
- 메모리 사용률 > 95%
- 서비스 다운

## 📊 대시보드 우선순위

### 🥇 **1순위: 사용자 경험**
1. HTTP 응답 시간 (P95)
2. 에러율 (전체 + 엔드포인트별)
3. 추천 성공률

### 🥈 **2순위: 시스템 안정성**
1. 메모리 사용량 트렌드
2. CPU 사용률
3. 컨테이너 상태

### 🥉 **3순위: 용량 계획**
1. 처리량 트렌드
2. 리소스 사용량 증가율
3. 데이터베이스 성능

## 🔍 문제 해결 워크플로우

### 📈 **성능 저하 발견 시**
1. **즉시 확인**: 에러 로그, 응답 시간 스파이크
2. **리소스 점검**: CPU/메모리 사용률 급증
3. **트래픽 분석**: 비정상적 요청 패턴
4. **스케일링 고려**: 리소스 한계 도달 시

### 🚨 **장애 대응**
1. **서비스 상태 확인**: 헬스 체크 실패
2. **인프라 점검**: 컨테이너/네트워크 상태
3. **롤백 고려**: 최근 배포와 연관성
4. **사용자 영향 최소화**: 트래픽 분산/우회
